# 花园道具与场景变化设计

本文件是前端可行性验证之后的设计稿，不代表列出的道具均已实现。当前代码由其他实现任务同步迭代；这里只记录设计、规则和验收方法。

设计开始：2026-10-31 22:46:10（Asia/Shanghai；工具时钟为 14:46:10 UTC）。下方保留实际多轮检查的时间与取舍。

## 先决定一局要带来什么

玩家在 30 秒内移动、观察、瞄准、打靶。道具应该让玩家看到“我的行动改变了花园”，并提供一个能立即理解的小选择。首版不做背包、装备栏、合成、稀有度和局外数值养成。

三个优先验证的道具是蓝泡泡瓶、弹簧蘑菇和花种。它们分别验证射击变化、移动变化和环境变化，统一采用走近自动拾取，不增加手机按键。道具本身不直接增加命中数；花种的作用也不能伪装成分数奖励。

这三个是主线实现任务计划落地的原型；下面给出建议的最终规则及风险。道具数值属于待真机体验的起点，不是已经验证的平衡结论。

截至设计开始时读到的代码：普通移动速度 4.8 m/s，跳跃初速度 8.1 m/s，重力 22 m/s²，射击间隔 0.25 秒，泡泡速度 18 m/s，普通泡泡模型半径 0.13 m；普通靶的球形命中判定半径是 0.68 m。现有 3 个靶命中后约 0.7 秒可再次命中。这些只是本次推算的基准，实际实现可能继续调整。

## 第一批三个道具

### 1. 蓝泡泡瓶：瞄准时更宽容，命中时更满足

**玩家看到的东西。** 一只矮胖透明感蓝瓶，瓶内有一颗大泡泡，底下有实心波纹标记；无需文字也能和蘑菇、花种区分。拾取后瓶子收缩成一道短蓝光进入泡泡枪，枪上显示蓝色水量刻度，新发射的泡泡明显变大。HUD 显示图标和剩余秒数，不只靠颜色表达。

**建议规则。** 持续 8 秒；命中有效半径先从 0.68 m 调到约 0.78 m；射速、弹速和分数均不变。大泡泡的可见尺寸与它的碰撞尺寸一起变化，避免“看着打中了却没中”。具体半径必须由“靶的碰撞半径＋泡泡半径”统一推导，不能在渲染与命中代码里各写一个无关的数字。

**碰撞和地形。** 不改地形、不穿箱、不穿墙。大泡泡也更容易被障碍挡住，这是玩家看得见的代价。需要在一段弹道里比较障碍和靶的最近碰撞点，不能因为先遍历靶就打中箱子后面的目标。

**恢复。** 到期只影响随后发射的泡泡；已在空中的泡泡保留发射时的尺寸。重复拾取只刷新到“当前游戏时刻＋8 秒”，不叠加半径，也不无限累加持续时间。正式 30 秒局里每个固定点只出现一次，因此通常不会发生无限刷新。

**公平性。** 路线和刷新位置固定；不随机生成在玩家脚下。每个命中仍为 1 分。不允许用它击中未经解锁或已经冷却的靶。个人记录按地图版本与规则版本区分。手机同样通过移动拾取，无需按技能键。

**成本。** CPU 每颗泡泡只多读取一个固定半径；复用现有弹道检测。GPU 不新增灯光、不新增全屏后处理，复用泡泡几何和材质；透明泡泡变大后覆盖像素变多，手机应限制同时存在的数量，不能仅看三角形数估算成本。

### 2. 弹簧蘑菇：改变移动路线，而不是强迫跳来跳去

**玩家看到的东西。** 有弹簧褶边的珊瑚粉蘑菇，拾取时压扁再弹起；角色脚边出现短暂弹簧圈。能力期间脚下的一小圈孢子轻轻升起，HUD 给出剩余秒数。它不是必须站在上面起跳的弹射平台；首版避免同时引入两套跳跃规则。

**建议规则。** 持续 8 秒；此期间主动起跳的初速度为普通值的 1.25 倍。走路速度和空中转向不变，仍需按空格或手机跳跃键，踩到道具不会突然把玩家弹飞。设计至少一条可选的低台地路线，让多出的高度有可见用途；主要靶位仍能通过普通步行路线到达。

注意，“初速度增加 25%”意味着理论跳高增加 56.25%，不是 25%。按上述基准，普通最大跳高约 1.49 m、同高落地的腾空时间约 0.736 秒；强化后分别约 2.33 m 和 0.920 秒。保持 4.8 m/s 的水平速度时，理论水平跨度由约 3.53 m 变成 4.42 m。实际坡地落点、加速过程和碰撞会改变结果。

**碰撞和地形。** 不即时抬高地面，只改变下一次起跳的初速度。墙外仍是不可进入的场景边界，不能因为跳得高就跳出可玩区。落地读取当前位置的真实地形；上坡可提前接地，下坡会延迟接地。顶到有实体底面的平台时需停止上升。当前若尚未实现顶面、侧面和底面碰撞，不应摆出看起来可以落脚却不能落脚的高台。

**恢复。** 起跳时记录本次竖直初速度；能力在空中到期时不突然下坠，也不把剩余竖直速度按比例缩回。空中拾取只影响下一次地面起跳。重复拾取刷新持续时间，不连乘。暂停时剩余时长不流逝。

**公平性。** 不把必打靶放在只有强化跳能到达的位置，避免错过道具便整局无解。原型阶段不给“跳射加倍”等隐含奖励。跳跃期间相机尽量稳定跟随，避免突然改变视角或扩大瞄准摇摆；要在手机上实际判断是否晕动。

**成本。** CPU 只是起跳时乘一个系数，碰撞成本主要来自地形和平台系统；GPU 使用少量共用几何的孢子，不增加实时点光源。更多跳高会暴露原先被墙挡住的远景，所以外围模型必须从高处看也完整。

### 3. 花种：让游戏结束后留下自己改变过的花园

**玩家看到的东西。** 一颗浅金色、带双叶芽的种子。拾取时落到附近预先选好的花床，花朵由小到大依次绽放，沿草坡铺成约 2～3 m 的短弧。结束时相机可以看到这片花，形成一局留下的痕迹。

**建议规则。** 本局第一次拾取后，约 0.8 秒完成开花，并保持到离开或重开本局。花种不增加伤害、命中判定或分数，不遮住靶，不生成新的碰撞体。它属于环境互动，可在结算旁用“今天开了几朵花”这样的独立小记录呈现，不能混进竞技命中数。

**碰撞和地形。** 花根采样地形高度，花朵沿表面法线轻微倾斜；花的生长只缩放显示节点，不抬升高度网格，不把玩家脚下的地面突然顶起。花床留出射线和走道，角色从花间穿过不会被小花卡住。

**恢复。** 每个花床最多开放一次，重开时回到含苞状态；切换地图清空旧花床；同一拾取事件重复派发也不会生出第二片花。编辑地形后重新采样花根，不让花浮在空中。

**公平性。** 固定的花床位置只负责反馈；挑战中不靠花种决定靶的可见性。采集它可以有几步绕路，但不能把它放在明显更优的必经点上同时宣称“这是一个选择”。手机依旧只需走近。

**成本。** 一片花床建议复用 2～3 种花型、按材质实例化；先给整个场景约 96 朵新增花的预算。CPU 只在开花阶段更新实例缩放，结束后停止更新；可用着色器做轻微摆动。GPU 使用不透明或裁切材质，避免层叠大面积半透明花瓣。这个数量是预算起点，必须真机测量。

## 组合效果与一局节奏

第一版地图可以让玩家在前 5 秒看到蓝瓶，在一次绕箱路线附近看见蘑菇，在坡脚的可选小岔路看见花种。摆放优先级是“容易理解位置”，不是强迫每个人沿同一条最优路线拾取所有东西。三个道具应该都能在出发画面或几步之后被看见，避免 30 秒快结束时才发现系统存在。

蓝瓶＋蘑菇同时生效时，保留各自的两个小图标；不要合成新技能，不改变第三个数值。一次拾取提示最多占一行，约 1.5 秒消失，不遮准星、不盖住手机右手区。拾取没有演出锁定，移动和射击继续。角色的长庆祝动作留在结算画面；在 30 秒局里强制庆祝 2 秒就吃掉约 6.7% 的时间。

蓝瓶把有效命中半径由 0.68 m 增至 0.78 m 时，正面近似命中圆的面积已增加约 31.6%。因此不再叠加磁吸、穿透、三连发或双倍分数。实际目标有深度和遮挡，这个面积比仅说明容错增长的量级，不是命中率预测。

一局开始前预加载完成并确认可操作，之后才倒计时。统一采用未暂停的游戏时钟：暂停冻结挑战、道具与世界；继续后不把后台经过的时间补算进去。物理可以拆成小步积分，不能因为某手机帧率低、每帧时间被截断，就让它的 30 秒挑战在现实中明显更长。

建议计分窗口为 `[0, 30)` 秒：30 秒前**实际命中**才算分，最后一颗泡泡在 30 秒后飞到靶上不算分。到点后可继续播短暂的非交互收尾动画，但不能继续触发道具或改变成绩。末秒拾取也不会延长挑战。

从旧代码推算，0.25 秒射击间隔对应理想上限约 120 次发射；这个上限不代表可稳定命中 120 次，弹道飞行、靶冷却、瞄准与帧调度都会限制结果。不能用随机奖励让一个人获得更多有效游戏时长，再把结果当成同一规则比较。

## 类型和状态转换建议

把规则状态与 Three.js 节点分开：模型负责显示；道具状态负责触发、结束和重置。下列是接口建议，不是已经接入项目的代码。

```ts
type PropKind = 'bubbleBottle' | 'springMushroom' | 'flowerSeed';
type TimedBuffKind = 'bubbleBoost' | 'springJump';

type PropState =
  | { tag: 'available' }
  | { tag: 'collected'; at: number };

type TimedBuff = {
  kind: TimedBuffKind;
  startedAt: number;
  expiresAt: number;
  sourcePropId: string;
};

type FlowerPatchState =
  | { tag: 'bud' }
  | { tag: 'blooming'; startedAt: number; duration: number }
  | { tag: 'bloomed' };

type RoundPhase = 'ready' | 'playing' | 'paused' | 'results';

type PropEvent =
  | { type: 'collect'; propId: string; gameTime: number }
  | { type: 'tick'; gameTime: number }
  | { type: 'reset'; mapId: string }
  | { type: 'mapChanged'; mapId: string };

type ProjectileSpec = {
  radius: number;       // 发射瞬间的快照，途中不再读取当前 buff
  speed: number;
  firedAt: number;
};
```

最小转换规则：

1. 只有 `playing` 或独立的自由练习状态可以收集；暂停和结算不触发。
2. `available → collected` 只发生一次；先提交状态，再播放视觉，重复碰撞事件没有第二次奖励。
3. 收集蓝瓶或蘑菇时，从不可变基础参数推导当前数值；禁止每次拾取执行 `speed *= 1.25` 之类的累乘。
4. `tick` 只删除到期 buff；当前在飞泡泡和当前跳跃保留既有状态。以到期时刻比较，避免大量分散的 `setTimeout`。
5. 花种由 `bud → blooming → bloomed`；使用固定花床 ID，重复事件不增加实例数量。
6. `reset` 一次恢复角色、道具、能力、花床、靶、泡泡和粒子；不能只把 UI 图标删掉。地图切换时也要清理旧地图状态。

拾取体采用简单圆柱或球体即可，但要校验高度范围，不能隔着上层平台拾到下层的瓶子。射击则使用沿上一帧到本帧的连续线段或扫掠体，并按碰撞距离选最近结果；泡泡大了以后，障碍体也要按泡泡半径扩张。

示例时间线：第 4 秒拾取蓝瓶，截止时间为第 12 秒；11.9 秒发射的大泡泡在 12.1 秒命中时仍然是大泡泡；12.2 秒的新泡泡恢复普通尺寸。若 11.8 秒强化起跳，12 秒能力到期也不能在半空突然削掉速度。这两条是最值得单独验证的边界。

## 用户自定义地形：允许，但先给容易做出好地图的工具

第一层做“花园布置”，用户选平缓花园、草坡山谷等预设，再调起伏、小山高度和宽度、远景颜色，以及在允许区域里摆靶和道具。第二层再加抬高、压低、平滑、压平的圆形笔刷。用户能在几次操作内做出可玩的图，比一开始就交付无限制的建模工具更有价值。

地形参数可以来自函数，但保存的是参数和高度数据，不必让用户输入 JavaScript。例如一座山采用 `A * exp(-r² / (2 * sigma²))`：`A` 是高度，`sigma` 控制宽度。它的最大坡度梯度为 `A / sigma * exp(-0.5)`；单座高 1.8 m、sigma 为 3 m 的山，最陡处约 20°，而高 3 m、同宽度时已约 31.2°。多个山包叠加后更陡，所以“每个滑块数值都合法”不代表组合地图可走，仍需检查生成结果。

### 编辑与游玩的边界

- 只在准备或编辑状态改变地形。挑战开始后锁定参数；进入编辑会退出当前挑战并回到自由试玩，不保留这局的正式成绩。
- 出生点附近保留约 2.5 m 的平缓安全区和一条通往主场地的走廊。用户可以看见这块保护区的轮廓，避免操作后不明白哪里没变化。
- 抬高地面后，草、箱、靶、道具与花床重新按同一高度网格落地；角色重新放到验证通过的出生点，再让用户试玩。
- 不默认把所有装饰模型都变成精细碰撞体。用户摆箱子可以有实体，花草默认为可穿过；编辑器直接显示碰撞轮廓和可走范围。
- 支持撤销、重做、恢复预设以及本地 JSON 导入导出。地图文件包含版本、种子、地形参数或样本、物件 ID 与位置；不包含需要执行的脚本文本。
- 自定义图单独保存个人成绩，记录地图内容标识和规则版本；不把容易刷分的小地图成绩与默认挑战比较。

作为原型，22 m 跨度的地面可以先用 65×65 个高度样本，间隔约 0.344 m；Float32 高度本身约 16.5 KiB。这个网格规格只是起点，应和实际控制器、坡面观感一起选择。显示和碰撞必须使用相同的三角形划分及插值；只在角色脚下直接算原始连续函数，却用稀疏三角网格显示，会产生脚浮空或陷地的差异。

### 地图检查需要回答什么

| 检查 | 处理 | 原因 |
| --- | --- | --- |
| 高度、坐标或缩放不是有限数，版本未知，样本数量不匹配 | 不应用，保留当前地图并给出具体位置 | 避免部分应用造成坏状态 |
| 出生点与障碍重叠，或出生坡度超过设定上限 | 不允许开始挑战，指出需要修复的位置 | 玩家必须能正常出发 |
| 走廊比角色直径窄 | 编辑器标红；按角色半径扩张障碍后计算 | 单看几何空隙会误以为能穿过 |
| 从出生点无法到达主要射击区域 | 不允许开始挑战；可保留为未完成草稿 | 地图需要有基本可玩路线 |
| 某个必打靶没有可到达且无遮挡的射击点 | 标出靶与遮挡物，要求调整 | “人能走到靶附近”不等于“枪口能看到靶心” |
| 可选道具位于陡坡或与其他物件相交 | 提示并提供吸附到最近合法地面的选项 | 道具应可拾取，且不会藏进箱子 |
| 远景物件误放入可玩区域，或新增花床遮挡靶面 | 显示范围提示；将装饰移回外围或降低高度 | 保持玩法可读性 |

可达性先在保守的可走网格上做连通搜索：考虑坡度、角色半径和障碍；然后从可达位置采样枪口到靶心的视线。它适合即时提示，但不等同于对连续运动的完整数学证明，最后仍要用同一套角色控制器试玩。高度场表示不了桥下通道和洞穴；“浮叶小桥”要等独立平台碰撞支持后再进入编辑器。

## 画风与角色动作的配合

对照 `experience/assets/01-arrival.png` 和 `02-practice.png`，道具应是少量、圆润、厚实的大形状：蓝瓶、珊瑚色蘑菇、浅金花种。保持奶油色高光、温暖阴影与低细节轮廓。不要用密集荧光描边和漂浮文字把小花园做成一片技能图标；每种道具既有颜色差异，也有足够不同的外形。

用户已经明确不满意临时黄色小龙的脸，角色外貌验收必须以用户认可的真实奶龙形象为目标。道具的技术验证不能替代角色美术验收，也不应把程序拼出的替代形象表述为官方模型。角色资源来源与可用范围由素材工作单独记录。

持枪姿态宜分成持续的双手托枪姿态和短暂的开枪反馈；走路时双腿运动，双手仍稳住枪。4 发/秒时一次反馈最好在下一发之前回到可继续叠加的状态，不能每发都播放完整“举枪—放下”动作。拾取只让眼神或头部短暂回应，不强制扭转整个身体，也不改变准星。重新加载或替换 GLB 时保留明确的手部、枪口和动作语义，避免把道具逻辑绑死到临时角色某个网格的名字上。

## 验收顺序与成本预算

先验规则，再看真实手机上的画面。以下是有必要检查的行为，不是声称本稿已执行的测试：

| 场景 | 通过标准 |
| --- | --- |
| 连续两次触发同一个拾取体 | 只有一次效果、一次提示和一个收集记录 |
| 重复获得同类能力 | 只刷新时长，不乘法叠加尺寸或速度 |
| 暂停 5 秒再继续 | 挑战和能力剩余时间都没有偷偷减少 |
| 大泡泡在能力到期后撞到靶 | 保留发射时半径；新泡泡恢复普通值 |
| 靶在箱后，泡泡同一帧经过箱和靶 | 箱子先挡住，不能隔箱算命中 |
| 强化跳跃途中能力到期 | 按当前竖直速度自然完成跳跃，不突变、不二段跳 |
| 角色站在上层平台、道具在下面 | 不隔层拾取；坡上的道具仍可正常取得 |
| 花床开放后重开或换地图 | 花床、道具、能力、泡泡、粒子和 UI 一起恢复，无旧实例残留 |
| 第 29.9 秒开枪，第 30.1 秒命中 | 这次不计入本局成绩，也不延长挑战 |
| 修改地形并撤销 | 地形、地面碰撞和附着物恢复一致；角色可从安全点再次出发 |
| 手机同时移动、拖视角、射击和跳跃 | 各触点按自身指针 ID 分工；抬起一个手指不会取消另一个动作 |
| 相同地图在低帧率运行 | 30 秒仍是相同未暂停时长，道具数值不会因帧数改变 |

第一批道具的建议预算：同时可见拾取物不超过约 6 个，新增花朵先控制在 96 朵左右，道具装饰粒子全场共用约 24 个名额。各类几何和材质复用；道具不新增动态灯光，细小花草不投射独立动态阴影。动画结束后停止逐实例 CPU 更新。现有泡泡继续保留上限，并优先池化、减少发射与命中时的临时分配。

这些是资源控制目标，不是帧率保证。应在目标手机上比较同一机位、同一分辨率下“关闭道具”“蓝瓶连射”“蘑菇跳到高处”“全场花朵开放”四种情况，分别观察帧时间、绘制调用、三角形数和透明覆盖。高处看到的远景增多、透明泡泡覆盖增大，可能比拾取瓶子本身更耗性能；只测试静止画面会漏掉这些成本。

完成第一批后再决定是否继续做风铃接力。花苞升台和浮叶桥需要支持动态支撑面、占用检测和安全恢复，暂时保留为明确的后续方案，避免为了演示地形变化而让角色掉进地面。
