# 三分钟演示：从一局花谷追击到类型安全的完整应用

总长 **180 秒**。按右侧时间推进，游玩不必现场通关。先展示玩家实际体验，再用同一局的记录解释架构。本文是演示脚本，实际执行证据见 [VERIFICATION.md](VERIFICATION.md)。演示使用当前 `drone-hunt-v2` 规则与真实账号记录；未通过的验收项应明确说明，不用旧截图代替证明。

## 开始前准备，不计入三分钟

- 打开成品前端首页，保持未登录；确认 Scala 与 PostgreSQL 已启动，健康检查、注册、开局、保存和历史查询均实际可用。不要把 `threejs/` 的独立原型当作完整应用。
- 预热模型缓存，重新回到首页。准备唯一的演示账号名和密码，使用密码管理器或粘贴输入，不花时间逐字打字；屏幕不展示密码明文。
- 试玩一次演示走位：先从扇区外命中一架**尚未发现奶龙**的无人机，观察高速搜索，再主动进入视野触发追击。已锁定且仍看得见奶龙的无人机受击会继续追击，不用于展示原地旋转。
- 准备一个已实际游玩并保存过胜利记录的演示账号，及其 `/results/:runId` 页面；这条记录仅作备用。记录日期和 RunId，不能临时伪造汇总数据充当通关。
- 如果有真实录屏，可准备 12–15 秒的「扫描 → 被发现 → 追击 → 爆炸」片段，画面明确标注“预先录制”。本稿不要求录制视频，也不假设现有截图包含移动追击。
- 编辑器只预开三个标签：`frontend/src/objects/training/RunId.ts`、`frontend/src/objects/records/ResultSubmission.ts`、`backend/src/main/scala/services/records/api/SaveTrainingResultAPIMessage.scala`。后端目录树展开 player / training / records 即可，不现场搜索文件。
- 开启计时器。三分钟期间不展示安装、编译、长日志或密码；失败备用动作也占所在时段，不追加时间。

## 180 秒逐段脚本

| 时间 | 屏幕动作 | 可以直接照读的口播 |
|---|---|---|
| **00:00–00:20 · 20 秒** | 停在首页 8 秒，指向角色画面、主按钮和“自由练习”。然后点击“开始挑战”。 | 「这是奶龙小靶场，一个浏览器里的单人追击游戏。打开先看到花谷和开始按钮，账号不会挡住第一眼。正式挑战会保存个人记录；下面的自由练习无需登录，只在本地体验。」 |
| **00:20–00:40 · 20 秒** | 在按需打开的账号弹窗切到注册，填演示账号并提交；成功后直接接续进入准备页。点击正式开始，给倒数留 3 秒。 | 「我刚才想开始挑战，所以现在才出现注册。注册成功会接着刚才的操作进入准备页，不用重新找入口。资源和局次准备好后才开始倒数，每一局都有自己的编号与规则快照。」 |
| **00:40–01:05 · 25 秒** | 观察无人机开局平滑升空。留在红色扇区外，展示血条；确认目标尚未发现奶龙后射击一次，观察高速旋转搜索，不连续击毁。若目标已锁定，换另一架未发现的目标，不把追击说成旋转。 | 「四架无人机会升空巡逻，每架三格血，红光是约九十度视野。我先从视野外打它一下：还没发现我的无人机会高速旋转搜索。已经锁定我的则会继续追击，不能靠连续开枪让它停在原地。」 |
| **01:05–01:30 · 25 秒** | 故意进入扫描区域，观察锁定后降低高度并快速追来；向箱边横移一次，再接近追击者，演示接触爆炸与失败弹窗。**到 01:20 仍未触发时立即用下面备用方案，01:30 准时切下一段。** | 「现在我主动暴露，它会降低高度、加速追来。我得借箱子或地形挡住视线，不能只靠直线跑开。接触就会爆炸并结束本局。这里故意演示一次失败，不要求在三分钟里现场通关。」 |
| **01:30–01:55 · 25 秒** | 指向结算的击毁、命中、发射与保存状态；看到真实“已保存”后点“再来一局”，展示重置的四机和新准备过程。随后通过明确的放弃操作回首页，打开我的记录。 | 「失败也保留这局真实的过程：击毁数和命中数是不同数据，结果会保存到开局账号。再来一局会创建新的局次。这里我放弃新开的这一局，它不会被冒充为一次完成成绩。」 |
| **01:55–02:15 · 20 秒** | 打开刚才完成局的记录详情，刷新页面，等待服务端重新返回。若改用预先保存记录，先说清来源。 | 「刷新后仍能看到这条结果，因为它来自数据库，不是页面里临时拼出的列表。最快通关只比较同规则、同地形的胜利记录。这里保存的是个人训练成绩，不声称仅靠汇总数字就能做到完整反作弊。」 |
| **02:15–02:50 · 35 秒** | 切编辑器，先指 RunId 与解码，再指 Save API；显示 player / training / records 目录。每处停约 8–10 秒，不滚长代码。 | 「结构沿用课程 sample：前端分 apis、objects、pages；Scala 按账号、局次、记录分模块，内部再分 api、objects、routes、tables、utils。RunId 和 PlayerId 不能混用；网络数据从 unknown 解码后才进入页面。API 的返回类型固定，后端用 IO 执行业务。保存时锁定本人局次，在一个事务里写成绩并结束局次；同一局重试不会重复记分。」 |
| **02:50–03:00 · 10 秒** | 回到首页或真实记录页，停止操作。 | 「这一版把进入游戏、追击战斗、胜败反馈和账号记录连成了完整闭环。下一步可以在这个基础上扩展道具和关卡。」 |

时长核对：20 + 20 + 25 + 25 + 25 + 20 + 35 + 10 = **180 秒**。口播不必填满每秒，给点击、倒数和观众观察留空白。

## 现场备用：不改变时间表，也不伪装现场结果

| 情况与切换点 | 立即动作 | 必须说清的话 |
|---|---|---|
| 注册请求超过 5 秒或失败 | 保留可见错误，尝试预先验证过的演示账号登录；若服务不可用，转练习演示玩法，后段用已保存记录证据说明限制 | 「注册这一步现场请求失败，我用预备账号继续。若后端暂时不可用，接下来展示本地练习，不能把它算作已落库。」 |
| 01:20 还未被锁定、追上或爆炸 | 切换真实预录片段；没有片段就暂停，展示当前已观察到的状态并描述待触发行为，不临时开启作弊或改代码 | 「追击触发具有位置条件，剩余这一段是事先录制的真实游玩。」没有片段时改为「现场这次尚未触发爆炸，这一点不能用当前画面证明。」 |
| 正式局保存失败 | 保留“尚未保存 / 重试”提示；不说落库成功。可按当前 UI 重试一次，继续下一段 | 「结果先留在本机待保存队列，当前还没写入成功。联网后会用同一局编号重试。」 |
| 01:55 没有本轮已保存记录 | 用预备账号打开既有真实结果页；先标明预先完成，再刷新 | 「这是演示前真实完成并保存的一局，不是刚才现场通关。刷新展示的是服务器查询。」 |
| 游戏性能不足或页面意外失焦 | 使用已经实现的低画质，或主动暂停并切真实录屏；不在三分钟内调驱动或重新构建 | 「当前展示切到较低画质 / 预先录制画面，玩法与保存流程不变。」 |
| 验收记录中某项仍未通过，或现场无法复现 | 依据 `VERIFICATION.md` 说明具体范围，展示实际状态；不把预期脚本当验证结果 | 「这一项当前没有通过现场验证，我只展示已经确认的部分。」 |

## 正式模式与练习模式，演示时不要混淆

| 项目 | 正式挑战 | 自由练习 |
|---|---|---|
| 入口 | 首页“开始挑战”，需要登录 | 首页“先自由练习”，无需登录 |
| 当前路由约定 | `/training` | `/training?practice=1` |
| 规则来源 | 后端开局返回的冻结配置与地形 | 前端练习默认值 / 本地地形 |
| 结果 | `victory` 或 `defeat`；按账号、RunId 保存 | 只本地预览，不进入账号历史或最佳 |
| 离开未完成局 | 正常放弃，不能写成完成结果 | 结束本地练习 |

三分钟内的“成绩落库与刷新”必须用正式局证明。`threejs/` 独立原型的截图、浏览器内计分和 localStorage 内容都不能单独证明 PostgreSQL 已保存。

## 当前规则提示卡，不增加口播时间

以下数值供演示者提前选好站位，不必在三分钟里逐个念出。当前版本为 `drone-hunt-v2`；正式局使用冻结的服务端配置。预备记录若来自旧 v1，应如实标注，不能作为当前 v2 的最快通关。

| 状态 | 当前表现 |
|---|---|
| 开局起飞 | 无人机中心相对地面从 0.82m，在 1.25 秒内平滑升至 2.2m |
| 巡逻与搜索 | 中心相对地面约 2.2m，巡逻速度 1.1m/s |
| 未发现玩家或当前视线被挡住时受击 | 高速旋转搜索，重新发现后切换锁定 |
| 锁定追击 | 降至相对地面约 1.2m，以 7.2m/s 追击 |
| 已锁定且仍看得见玩家时受击 | 继续追击，不被受击搜索打断；达到致命伤害仍正常击毁 |

高度是无人机中心相对当地地面的目标高度，随起飞或追击状态平滑变化，不是地形世界坐标，也不是模型底部高度。

## 讲架构时对应的真实代码位置

- [当前 API 契约](API_CONTRACT.md)：公开请求与响应、`victory / defeat`、`destroyed`、规则快照、归属和重试语义。口播使用“击毁数”对应 `destroyed`，不沿用旧“命中一个靶等于一分”。
- `frontend/src/apis/player/`、`frontend/src/apis/training/`、`frontend/src/apis/records/`：按 sample 分服务的 API 调用类；系统层统一发请求和加令牌。无需在台上展示完整 URL 列表。
- `frontend/src/objects/training/RunId.ts` 与 `frontend/src/objects/player/PlayerId.ts`：分别定义品牌 ID，并从实际 UUID 校验结果构造。编译期区分 ID 与运行时 JSON 校验是两层能力。
- `frontend/src/objects/records/ResultSubmission.ts`：从 `unknown` 检查整数、结果枚举与基本关系。最终规则和归属仍由后端再检查。
- `frontend/src/system/api/APIMessage.ts` 与 `backend/src/main/scala/services/system/api/APIMessage.scala`：类型化响应与 `plan(connection): IO[Response]`；不把 IO 解释成自动拥有授权或事务。
- `backend/src/main/scala/services/records/api/SaveTrainingResultAPIMessage.scala`：本人局次锁、重复提交比较、结果插入与局次完成；事务外层由 system 管理，表层封装 SQL。
- `backend/src/main/scala/services/{player,training,records}/`：按微服务职责组织，当前运行在同一个 Scala 进程；不要把目录模块说成已经独立部署的三台服务。
- `frontend/src/pages/Training/game/core/`：前端渲染、输入、碰撞与无人机循环。每次射击不请求后端，不用 WebSocket；后端负责身份、规则版本、局次和最终记录。

上述代码路径与契约用于解释实现；启动、注册接续、实机爆炸、数据库刷新等执行证据以 [VERIFICATION.md](VERIFICATION.md) 中的实际记录为准。录屏只是可选备用，本稿不代表已有演示视频，也不从“文件存在”推断整条流程已经验收。
