# 花谷扩展验收追踪

日期：2026-11-01。范围：`IMPLEMENTATION_CONTRACT.md` 所约定的任务、世界版本、地图工坊、过程事件与回放。

本文件由独立验收代理维护。当前已完成部署后 HTTP 协议验收，下列项目区分实际执行、测试报告与仍待验证部分，不因阅读代码而视为通过。基线的历史验收见 `VERIFICATION.md`，不能替代扩展完成后的回归。实际浏览器 B 项由主代理继续验收。

## 执行边界

- 本轮不启动、停止或重启服务，不连接数据库执行 SQL，不删除或清空任何现有账号、局次或表。
- `scripts/verify-expansion.mjs` 默认只输出计划，不访问网络。接口落地后才能用 `--write-fixtures` 执行；它仅接受本机回环地址，通过 HTTP 注册两个全新 QA 账号，并只修改这两个账号产生的记录。它不会读取 `.env`、用户令牌或浏览器数据。
- HTTP 脚本提交的成绩是明确的协议测试数据，不构成真实游戏通关、真实性反作弊或视觉正确性的证据。
- 事件与回放精确 v1 结构现已补入实施契约，脚本据此构造明确的协议 fixture；浏览器实际录制、独立断网补传和容量边界仍为独立 PENDING 项。不得把局部 API 检查称为整体验收通过。
- 脚本不删除 QA 数据；结尾注销新建会话。没有后台清理所有权不明的数据的步骤。

## 已阅读的运行链路

- 前端正式入口 `5173`、生产预览 `4173` 都把 `/api` 代理到 `127.0.0.1:8080`。`sendAPI` 从类名生成小写路径，身份放 JSON 的 `userToken`，不是 Bearer Header。
- `/api/health` 是 GET；业务接口都是 POST，成功是直接 DTO，错误是 `{code,message}`。
- `scripts/test-backend.ps1` 经 `invoke-backend.ps1 -TestDatabase` 选择 `.env` 的 `DB_TEST_NAME`。现有 Scala 集成套件进一步要求数据库名以 `_test` 结尾，并为各用例创建自己的账号；没有清空共享业务表的动作。
- 后端后台模式是编译后运行 `services.system.Main`。改源码不会自动替换已启动的 Java 进程；谁负责重启由主代理协调，本验收代理不自行重启。
- 前端测试、核心测试、后端集成测试覆盖层次不同；类型检查和构建不能替代实际浏览器交互。

## 需要对齐的兼容边界

1. `selection/setup/objectiveProgress` 的缺失与 null 必须兼容旧请求、旧行和旧待上传项；幂等比较同时包含新增业务字段。
2. 现有 `PendingResultQueue.decodeItem` 严格限制旧成绩五字段，扩展时须同步更新并保留旧数据解码。成功响应的同内容校验也要比较 `objectiveProgress`。
3. 当前个人最佳筛选只有配置版本与地形；撤离胜利不能因此覆盖原四机清除的最快成绩。新任务、地图版本、工具的可比性需要明确。
4. 原统一 HTTP 请求预算是 16 KiB；地图、事件和回放需要各自有界预算，不能为录像放宽全部认证接口。UTF-8、非法 JSON 和错误形状要继续一致。
5. 地图草稿 revision 与不可变 MapVersion 分离；局次冻结地图、任务、规则、seed、工具和素材版本，不跟随最新草稿变化。
6. 自定义地图的目标 marker ID 要映射到冻结世界；后端不得相信客户端传来的 setup、归属或胜利条件。
7. 新目标按冻结目标判胜负。自定义无人机数量取冻结世界，不能始终取旧 `config.drones.spawns` 数量。
8. 门开启后必须同步取消移动、射击和视线遮挡；回放与时间跳转也要恢复正确门状态。
9. 原成绩允许最长 24 小时，回放必须有容量上限与完整/片段覆盖声明；不能让超长局无限占用内存，或把片段伪称完整录像。
10. 先保存成绩，再独立补传事件与回放。任一补传失败不能丢成绩、重复建局、向另一账号提交或在播放时触发保存。

## 验收命令

```powershell
# 只展示计划，不访问网络、不创建记录。
node ./scripts/verify-expansion.mjs

# 主代理确认接口已部署后，显式创建全新 QA 数据；不修改既有账号数据。
node ./scripts/verify-expansion.mjs --write-fixtures --base http://127.0.0.1:8080

# 独立后端测试库；请由主代理协调是否已有其他 sbt 测试运行。
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/test-backend.ps1
```

脚本退出码：0 为当前实现检查全部通过且没有待补项；1 为实际检查失败；2 为已运行检查通过但仍有明确 PENDING 项。默认计划模式不执行检查，返回 0 不代表验收通过。
