# 奶龙小靶场：完整应用的界面方向

这份说明用于实现首页、账号、游戏外壳、记录和设置。它继承用户确认的「左边是奶龙与花园，右边是主菜单」，玩法文案按当前四架无人机版本更新：巡逻、扫描、追击，碰撞爆炸即失败，全部击毁获胜。旧体验 PDF 中的 30 秒、固定圆靶、联机设置说明不再用于当前产品界面。

本文是具体的实现方案；并不表示以下页面已实现。视觉资产来源与实际游戏截图单独标明。

## 1. 视觉方向与基础组件

界面像一本打开的花园冒险手册。奶油色纸面、深青字色和琥珀色重点，与现有场景的绿色、奶龙的黄色相接。首页使用大幅角色画面与清楚的菜单，历史页使用紧凑的记录列表；避免每一项文字都套成一张浮动卡片。

| Token | 初始值 | 用途 |
|---|---|---|
| `--paper` | `#F8F6EA` | 页面底色 |
| `--surface` | `#FFFCF2` | 菜单和弹窗 |
| `--ink` | `#173F3C` | 标题、正文 |
| `--muted` | `#62736A` | 辅助文字；实现时检查实际背景对比度 |
| `--primary` | `#17665D` | 开始、继续、保存等主要按钮 |
| `--primary-hover` | `#0D514A` | 主要按钮悬停 |
| `--amber` | `#F3BF56` | 奖章、选中点、轻提示；不作为浅底小字 |
| `--danger` | `#B74435` | 失败、错误、放弃 |
| `--line` | `#DDDCCB` | 分隔线与输入边框 |
| `--focus` | `#287DB2` | 键盘焦点环，留 3px 间隙 |

字体沿用设备中文无衬线：`"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。标题用较高字重与适度紧凑字距；主要标题 36–52px，页面正文 15–17px，辅助信息至少 12px。数字使用 `font-variant-numeric: tabular-nums`，避免计时与命中数跳动。

页面外缘大圆角 28px，弹窗 24px，按钮与输入框 14px；桌面主按钮高 56px，次按钮 48px，所有触控入口至少 44px。按钮使用真实文字和少量统一 Lucide 图标；不用 emoji 承担关键状态。阴影仅在菜单和弹窗使用柔和深青低透明度阴影。

sample 已提供 React、Tailwind 4、Radix Dialog/Tabs/RadioGroup、react-hook-form 与 lucide-react。沿用 `src/components/ui/` 的基础组件，并在 `src/index.css` 定义主题变量。页面业务仍按 `pages/<Page>/{components,hooks,objects}` 组织，接口与对象分别放 `apis/<service>/`、`objects/<service>/`。不引入第二套完整 UI 框架。

借鉴的是成熟组件的交互能力，视觉由本项目重新定义。[Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) 提供模态焦点约束、标题描述与 Esc 支持；[shadcn 的 Radix Dialog 组合方式](https://ui.shadcn.com/docs/components/radix/dialog)适合现有 sample。不要直接运行最新默认模板覆盖 sample；当前 shadcn 文档也有其他底层实现，应明确选择 Radix。

## 2. 首页：先看见游戏，再登录

桌面最大内容宽度约 1440px，外侧 24–40px 留白。顶部是小号品牌与「单人 · 花谷巡猎」，右侧是登录/注册或当前昵称。主体是约 60:40 的左右布局：左侧大画面，右侧 360–420px 宽的菜单。右侧留白比按钮间距大，第一眼只突出一个主动作。

右侧文案与顺序：

1. 小标签「BLOOM VALLEY · SOLO」。
2. 大标题「奶龙小靶场」。
3. 副标题「躲开红光，守住这片花谷。」
4. 一行规则：「4 架无人机 · 被发现会追击 · 全部击落即获胜」。
5. 主按钮「开始挑战」，旁边箭头；进入准备页，不在首页点击后立即开战。
6. 次按钮「我的记录」。
7. 更轻的「设置」与「操作说明」入口。

登录态检查在顶部显示小型进度，不用整页骨架替换主视觉。尚未登录点击挑战或记录才打开账号弹窗；右上角主动登录成功后留在首页。关闭弹窗清除待执行动作，不后台开局。注册成功直接登录并接续同一个动作。

图片左下角可放一枚简洁的「花谷手记」标记，但不要把技术信息（Three.js、GLB、类型安全）放进玩家流程。素材声明放轻量图注或「关于」区域，不抢主动作。

## 3. 账号弹窗

桌面宽 420–460px；奶油色面板，顶部一枚小叶片或品牌形状，标题「先给这次冒险起个名字」。用登录/注册 Tabs 切换，保持账号字段，密码不持久化到本地。注册有账号、密码、确认密码，首版昵称沿用账号名称。

每个输入框上方有真实 Label，不把 placeholder 当 Label。用户名使用 `autocomplete="username"`；登录密码为 `current-password`，注册和确认密码为 `new-password`。密码可见按钮有明确可访问名称。确认密码仅前端检查，不进入 API 请求。

表单状态用有区分的状态表示：编辑、提交中、字段错误、服务错误、成功。提交中保留内容并禁止重复提交，按钮改为「正在登录…」或「正在创建…」。请求失败保留账号，给出可重试的说明。账号冲突定位账号字段；密码不匹配定位确认字段；登录失败使用后端统一的安全文案。未知错误显示「暂时无法完成，请重试」，不显示数据库或堆栈信息。

弹窗开启时焦点进入第一个输入；Tab 留在弹窗内。关闭后返回原入口；登录成功进入准备/记录页时，焦点转到新页标题。切换 Tab 不提交表单。提交过程中即使允许关闭，也必须取消“登录后自动继续”意图，避免稍晚的响应把用户突然带入游戏。使用 `Title`、`Description` 与字段 `aria-describedby`，字段错误设置 `aria-invalid`。这些结构参照 [shadcn Field](https://ui.shadcn.com/docs/components/base/field)；不需要为此更换现有表单库。

## 4. 游戏准备、HUD 与爆炸失败

准备页保留当前 Three.js 实景。上方缩为一条品牌导航，提供「回主菜单」「设置」。画布占主体，说明浮在不遮挡角色的左上区域，右上显示挑战目标。正式开始以前显示「四架无人机正在巡逻」以及三条规则：避开红色扇区、受击敌机会加速搜索、接触爆炸会结束本局。主按钮「进入挑战」在固定、明显的位置。

资源加载状态显示真实阶段：场地、角色、无人机；无法准确获得字节比例时用阶段文字与不定进度，不伪造 99%。资源失败提供「重新加载」与「回主菜单」。按钮仅在资源与服务端局次条件就绪后可用。

正式 HUD 只保留：击毁 `0 / 4`、用时、暂停。命中与发射统计放辅助层或结算，不增加大面板挡视线。无人机血条贴近对象上方；红色扫描加方向和状态文字，不仅靠颜色区分。锁定时有短文字「被发现了，快躲开！」，不要持续闪屏。移动和射击仍在 Three.js 中执行，React 订阅低频 HUD 快照，不每帧重绘整页。

碰撞爆炸时先锁定唯一结束事件与不可变结果，停止输入、无人机伤害与计分；播放短爆炸，再打开结果弹窗。爆炸可继续渲染但不能产生第二次死亡或保存。减少动态效果设置下取消镜头震动与强闪光，仍保留爆炸形状、声音与失败文字。弹窗出现后画布输入完全停用。

## 5. 胜败结算

结算是一张 520–600px 宽面板，保留背后冻结的实际场景。成功使用琥珀小徽章与「花谷安全啦！」；失败使用温和陶红图形与「被无人机追上了」，第二行说明「避开扫描，利用箱子和山坡拉开距离」。不使用嘲讽语气或把失败伪装为胜利。

主数据是击毁数与用时：成功 `4 / 4`，失败保留实际击毁。下一行是命中、发射与命中率；命中率零次射击显示「—」。一架无人机三点血，因此“击毁”和“命中”必须分开，不再把一次命中直接当一架。

下方保存状态独立于胜败：

| 保存状态 | 表现与操作 |
|---|---|
| 保存中 | 小进度与「正在保存本局」；立即可看结果 |
| 已保存 | 小勾与「已记入你的挑战记录」 |
| 网络失败 | 「本局已暂存在这台设备，联网后可重试」+「重试保存」 |
| 登录过期 | 「重新登录后保存本局」；必须是开局账号 |
| 账号不同 | 「这局属于另一账号」，保留待保存记录，不代提交 |

底部主按钮「再来一局」，次按钮「回主菜单」，另有轻入口「查看记录」。再来一局必须取得新的局次，不复用旧 RunId。弹窗不因点击背景突然消失；Esc 可进入可控的结束后页面或回到同样的静止结算区域，绝不恢复已结束游戏。

## 6. 我的记录与单局详情

记录页沿用奶油纸面；左上返回首页，标题「我的花谷记录」，副标题是当前玩家昵称。顶部是一条简洁摘要：同规则的最快通关、已通关局数和最近结果。没有通关时最快时间显示「尚未通关」，不显示 0 秒。

下面每行记录：胜/败标记、日期时间、击毁数、用时、命中率、详情箭头。桌面可用语义表格；手机变为单列记录条，但字段顺序保持一致。最新记录在前。分页使用明确的「加载更多」与加载反馈，不无限拉长页面，也不要求一次取全部历史。

首次无记录时显示「第一段冒险，从这里开始」，配一个小图形与「开始挑战」。加载用 3–4 条固定高度骨架；失败展示错误与重试，不能误显示成没有记录。分页失败保留已加载内容，重试只作用于下一页。未知规则版本可展示原始规则标签，不能与当前版本混算最佳。

单局详情可独立刷新：从经过校验的 URL RunId 查询。状态明确区分已完成、未提交、已放弃、不属于当前用户/不存在、请求失败。失败局是正常完成记录的一种结果，不等同网络加载失败。旧“30 秒完成”约束需随新玩法重写。

## 7. 设置、响应式与交互验收

设置包含画质、主音量、边缘转向速度、镜头距离；可增加“减少动态效果”，但只有已经接到引擎的选项才显示。画质使用低/中/高三段单选，解释低画质主要减少装饰与阴影；操作相关对象、扫描区与血条都保留。音量与速度支持键盘调整，并显示当前值。原生 range 或现有组件即可；[Radix Slider](https://www.radix-ui.com/primitives/docs/components/slider)可作为键盘与标签实现参考。

主菜单设置关闭即回主菜单。游戏中打开设置立即暂停所有运算并清空长按；继续需主动点击并倒数，不因关闭浏览器菜单而自动继续。失焦返回同样保持暂停。放弃返回首页有明确确认，其视觉弱于继续；取消是默认焦点，确认放弃才调用后端状态转换。

| 视口 | 布局 |
|---|---|
| ≥ 1024px | 首页左右双栏；游戏使用可用高度，HUD 避开瞄准区 |
| 640–1023px | 主视觉适当收小，右侧菜单至少 320px；空间不足转上下布局 |
| < 640px | 顶部品牌与账号；短主视觉；标题与主按钮在首屏可见；次操作置后 |
| 手机横屏游戏 | 画布铺满主要区域，安全区内放虚拟摇杆、瞄准/射击、跳跃与暂停 |
| 手机竖屏游戏 | 提示横屏体验更好，但仍允许操作；HUD 缩短、触控区不盖主目标 |

弹窗最大高度 `calc(100dvh - 32px)`，内容可滚动，底部动作可固定；考虑 `env(safe-area-inset-*)`。手机键盘出现时提交按钮仍可滚到。避免仅 hover 的关键说明。不要要求进入网页就全屏或锁定指针。

动画控制在 160–220ms，主要是按钮与弹窗出现；`prefers-reduced-motion` 下取消位移和无意义循环动画。键盘可完成首页、登录、设置、记录、结算整个流程。对话框初始焦点与关闭后焦点按照 [WAI-ARIA 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)处理；复杂结算可先聚焦标题，让读屏按结构阅读。

## 8. 类型与接口需求

以下是页面必需的语义，最终名称由前后端共同契约确定。网络 JSON 必须先经运行时解码，再进入页面；业务层不能依靠 `as TrainingResult` 把未知对象当作已验证结果。

| 数据/状态 | 必须区分的内容 |
|---|---|
| `PlayerSessionState` | checking / signed-out / signed-in(player) / 恢复失败；网络不可用不等同明确退出 |
| `PendingHomeAction` | start-training / open-history / none；关闭登录清除 |
| `AuthDraft` | mode、username、password、confirmPassword（仅注册本地） |
| `PageState<T>` | loading / empty / ready(data) / failed(error)；分页加载与分页失败保留原 items |
| `TrainingConfig` | configId、rulesVersion、四机参数、血量、扫描/移动/爆炸规则、武器参数 |
| `TrainingRun` | RunId、归属、配置快照、状态；开局请求有幂等 requestId |
| `FinishedRun` | outcome = won / lost；kills、hits、shotsFired、elapsedMs；失败原因如 drone-collision |
| `SaveState` | saving / saved(result) / retryable-failure / reauth-required / owner-mismatch |
| `PendingResult` | owner PlayerId + RunId + 不可变 submission；重试相同内容 |
| `PersonalBest` | 同 configId / rulesVersion 的成功局；最快有效 elapsedMs；无数据是 null |
| `LocalSettings` | 有界画质/音量/转向/镜头值，解码失败回默认；不写成额外微服务 |

后端至少提供注册、登录、恢复身份、退出；配置、开局、查局、放弃；保存成绩、查成绩、本人历史、同规则最佳。保存失败局也属于正常结束；没有击毁但被追上依然可有记录。前端不提交任意 playerId 来决定归属。响应错误码映射为可操作的界面状态，未知错误有兜底。UI 不把 API 错误状态与游戏失败结果混用。

## 10. 实现检查点

- 新访客先看到游戏菜单；登录成功接续动作，关闭账号窗不会误开局。
- 账号的加载、冲突、错误、过期都有明确界面，键盘焦点正常。
- 开始、结束、重开按钮不会点击穿透成一次射击。
- 四机全部击毁与接触爆炸失败只有一个最终结果；结算立即显示，保存可独立重试。
- 历史显示数据库真实记录，空状态与网络失败分开；无截图式假记录。
- “最快通关”只比较同规则胜利局，零发命中率为「—」。
- 设置真实影响引擎并保存在本机，失焦与弹窗期间游戏暂停。
- 390px 竖屏、844px 横屏、1280px 桌面检查布局与触控；登录和结算的操作可完整看见。
- 动态效果不影响减少动作偏好；文字、颜色、焦点环在实际背景上验证。
